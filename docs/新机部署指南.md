# 新机部署指南（给另一台电脑上的 Codex / 人类执行者）

> 目标读者：在一台**新的 Windows 电脑**上，想用本仓库把 Codex Desktop 接入多厂商模型网关的你（人类或 AI Agent）。
> 原则：**能用就行**。核心只有两件事——① 网关跑起来；② Codex 客户端指向网关。`js_repl` 补丁是可选保险，不要求启用。

---

## 0. 这是什么

`bridge/kimi_bridge.py` 是一个本地网关（`127.0.0.1:15731`），把 Codex Desktop 发出的 OpenAI Responses 协议请求，智能路由到 Kimi / 智谱 / MiniMax / Gemini / 任意自定义 OpenAI 兼容上游，并处理协议改写（tool_search 孤儿调用、namespace 展平、key 动态注入、`gpt-5.6-luna` 后台任务别名重写等）。附赠一个暗色仪表盘。

---

## 1. 前置条件

- Windows 10/11，已安装 **Codex Desktop**
- **Python 3.11**（勾选加入 PATH），或自备 python.exe 路径
- 至少一家上游的 API Key（智谱 / Kimi / MiniMax 等）
- git（用于克隆本仓库）

## 2. 克隆仓库

```powershell
git clone https://github.com/a593477311-lgtm/codex_root.git E:\codex_root
cd E:\codex_root
```

## 3. 安装依赖

```powershell
pip install fastapi uvicorn httpx
```

## 4. 部署网关运行目录

把 bridge 运行文件复制到 `~\.codex\tools`（这是网关的正式运行目录，与仓库解耦）：

```powershell
$tools = "$env:USERPROFILE\.codex\tools"
New-Item -ItemType Directory -Force "$tools\assets" | Out-Null
Copy-Item E:\codex_root\bridge\kimi_bridge.py   $tools\ -Force
Copy-Item E:\codex_root\bridge\dashboard.py     $tools\ -Force
Copy-Item E:\codex_root\bridge\dashboard.html   $tools\ -Force
Copy-Item E:\codex_root\bridge\bridge_stats.py  $tools\ -Force
Copy-Item E:\codex_root\bridge\assets\*         "$tools\assets\" -Force -Recurse
```

## 5. 生成自己的网关配置（不要把 key 提交进 git！）

```powershell
Copy-Item E:\codex_root\bridge\bridge_config.example.json "$tools\bridge_config.json"
notepad "$tools\bridge_config.json"
```

编辑要点（`bridge_config.json` 已被 .gitignore 排除，安全）：

- `providers` 里每个渠道填**你自己的** `key`；用不到的渠道留占位符即可
- `active_provider`：当前生效渠道（如 `"zhipu"`）
- 各渠道 `active_model`：该渠道默认模型（如 `"GLM-5.3-Flash"`）
- `host` / `port` 保持 `127.0.0.1` / `15731`

## 6. 后台启动网关（独立于任何 IDE / Agent）

```powershell
$pyw = "$env:LOCALAPPDATA\Programs\Python\Python311\pythonw.exe"
if (-not (Test-Path $pyw)) { $pyw = "pythonw.exe" }
Start-Process -FilePath $pyw -ArgumentList "`"$tools\kimi_bridge.py`"" -WorkingDirectory $tools -WindowStyle Hidden
```

或直接用仓库自带脚本：`E:\codex_root\scripts\start_bridge.bat`（停止：`stop_bridge.bat`）。
想开机自启：`powershell -File E:\codex_root\scripts\install_autostart.ps1`（注册登录计划任务 `CodexKimiBridge`）。

## 7. 把 Codex 客户端指向网关

编辑 `~\.codex\config.toml`（没有就新建），确保以下内容：

```toml
model_provider = "custom"
model = "GLM-5.3-Flash"            # 与网关配置中的 active_model 一致
model_reasoning_effort = "xhigh"   # 可选
model_catalog_json = "models.json"
model_context_window = 1000000

[model_providers.custom]
name = "kimi_coding"
base_url = "http://127.0.0.1:15731/v1"
wire_api = "responses"
requires_openai_auth = true
```

编辑 `~\.codex\auth.json`（没有就新建）：

```json
{ "OPENAI_API_KEY": "sk-bridge-local" }
```

> 这里**随便填非空占位符即可**——出站请求由网关动态注入真实 key，客户端这个值不参与上游鉴权。

## 8. 验证（全部通过即部署成功）

逐条执行，括号内是期望结果：

```powershell
# 1) 端口在听
Get-NetTCPConnection -LocalPort 15731 -State Listen | Select-Object -First 1
# （返回一条 LISTEN 记录）

# 2) 仪表盘 HTTP 200
(Invoke-WebRequest "http://127.0.0.1:15731/dashboard" -UseBasicParsing).StatusCode
# （200）

# 3) 网关->上游全链路真请求
python -c "import json,urllib.request;p=json.dumps({'model':'GLM-5.3-Flash','input':[{'role':'user','content':'ping'}],'stream':False}).encode();r=urllib.request.urlopen(urllib.request.Request('http://127.0.0.1:15731/v1/responses',data=p,headers={'Content-Type':'application/json'},method='POST'),timeout=60);print('HTTP',r.status)"
# （HTTP 200）

# 4) 浏览器打开 http://127.0.0.1:15731/dashboard
# （统计卡/趋势图有真实数据；渠道中枢能看到你配置的供应商）
```

然后重启 Codex Desktop，在模型菜单里应能看到 `models.json` 中注册的自定义模型（网关在添加/保存渠道时会自动注册）。
**最终验收标准：在 Codex 里正常对话、模型流式回复、仪表盘「请求明细」出现新记录。**

## 9. js_repl / FALSE-TRUE 补丁（可选保险，默认不做）

客户端功能由账号/远端仲裁，本地 `config.toml` 里 `features.js_repl` 的值**不代表实际生效状态**（实测存在 `= false` 但工具全部正常的情况）——多数情况下工具本来就可用，桥接与它互不替代。
**只有当某天客户端本地工具（js 等）真的被禁用时**才执行：

```powershell
powershell -File E:\codex_root\client_patches\patch-js_repl.ps1   # 从干净备份重建补丁副本
# 之后改用补丁副本启动 Codex：
& "$env:LOCALAPPDATA\Codex-patched\<版本目录名>\app\Codex.exe"
```

验证补丁副本：`powershell -File E:\codex_root\client_patches\verify-js_repl.ps1`
（Phase 1 全 PASS 即达到"防反写"目的；Phase 2 两项 FAIL 可忽略，不影响"能用"目标。）

## 10. 常见问题

| 症状 | 处理 |
|---|---|
| 端口没起来 | 看 `~\.codex\tools\kimi_bridge.log` 最后 50 行；常见是依赖没装或端口被占（`stop_bridge.bat` 后重开） |
| 对话报 401 | 网关配置里对应渠道 key 错误/失效，仪表盘「渠道中枢」里改 key（免重启热切） |
| 报 503 且客户端高频重试 `gpt-5.6-luna` | 正常已被网关别名机制重写为主模型；若仍出现，确认 kimi_bridge.py 为仓库最新版 |
| 模型菜单里没有自定义模型 | 确认 `config.toml` 的 `model_catalog_json = "models.json"`，并在仪表盘重新保存一次渠道触发模型注册 |
| 推理强度只剩一个选项 | 已修复：网关自动注册完整 4 档（low/medium/high/xhigh）；确认 dashboard.py 为仓库最新版 |

## 11. 安全铁律

- `bridge_config.json`、`auth.json`、任何真实 key **绝不**提交进 git（.gitignore 已挡，别用 `git add -f`）
- 历史上本仓库泄露过一个智谱 key 并已轮换作废——教训：连 example 文件也只放占位符
- 在公共场合分享截图前，检查是否带 key / token
