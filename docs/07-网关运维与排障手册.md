## 启动 / 停止 / 自启

```powershell
# 手动启动
Start-Process pythonw.exe -ArgumentList "$env:USERPROFILE\.codex\tools\kimi_bridge.py" -WindowStyle Hidden

# 确认在听
Get-NetTCPConnection -State Listen -LocalPort 15731

# 停止
Get-Process pythonw | Where-Object { (Get-CimInstance Win32_Process -Filter "ProcessId=$($_.Id)").CommandLine -match 'kimi_bridge' } | Stop-Process -Force

# 注册登录自启（需要用户明确同意）
powershell -File scripts\install_autostart.ps1
```

## 故障排查决策树

**Codex 报 `Invalid request Error` 秒挂（1-2 秒内）**
→ 桥没在听，或 Codex 进程缓存了旧 base_url。先查 15731 端口，再完全重启 Codex。

**Codex 报 `tool type "..." is not supported`**
→ 出现了桥没覆盖的新工具类型。看桥日志的 tools 抓包，把新类型加进 `normalize_tool` 的转换（或 `SPECIAL_CALL_TYPES`/`SPECIAL_PARAMS`）。

**Codex 报 `not a valid moonshot flavored json schema`**
→ 新 schema 形状。看报错里的 path；若是 `$ref` 之外的兼容问题，扩展 `sanitize_schema`。

**模型空转 echo placeholder、工具调不出来**
→ deferred 工具没注入。看桥日志有没有 `injected N deferred tools`；没有则检查历史里的 `tool_search_output` 是否带 `tools` 字段。

**工具调用 aborted / `unsupported call: xxx`**
→ 响应路径没还原成原生项。确认该工具名在 `special_names` 里（转换时会注册）；若是 namespace 动态工具，查 `namespace_map.json` 有没有该映射（没有说明映射还没学到——让模型先成功跑一次 tool_search）。

**Codex 报 `tool_call_ids did not have response messages`**
→ 历史里有孤儿调用（app 只记录不执行的服务端语义工具，如 web_search）。桥 7 层以后的版本会自动合成占位结果项修复；若仍报，检查桥版本并看日志有没有 `synthesized function_call_output for orphan call`。

**一切 200 但行为怪异**
→ 看桥日志对比"抓包的 tools"与"转换记录"，确认没有误伤。

## 与 cc-switch 共存（或移除）

cc-switch 会改写 `~/.codex/config.toml` 的 `base_url` 指向它自己的代理，与本桥冲突。二选一：

- **用本桥**：在 cc-switch 设置里关闭 Codex 的本地代理接管 + 关开机自启（或删 `HKCU:\...\Run` 里的 `CC Switch` 项）。注意它的"退出时恢复配置"恢复到接管前状态，不是回官方。
- **用 cc-switch**：把 `base_url` 还给它，但第 2/3/4/5/6 层的协议问题它一个都不处理，`tool_search` 等会挂。

## 回退到直连

`config.toml` 的 `base_url` 改回 `https://api.kimi.com/coding/v1`，完全重启 Codex。桥进程杀不杀都行（没人连它）。直连后 `tool_search`、动态工具、部分 schema 会恢复 400——这是预期。

## 安全注意

- 桥日志含完整 tools 定义（无 key），但**不要**把它提交进 git（`.gitignore` 已排除）
- `~/.codex/auth.json` 是 Kimi key 的唯一存放点，桥只是透传 Authorization 头，不记录
- 历史上出现过明文 key 落地（`kimi_upstream_key.txt` 等），部署时检查 `~/.codex/tools/` 和 `%TEMP%` 有无残留 key 文件
