# 03 验证清单与踩坑记录

## 静态验证（对最终 app.asar 做，不看源目录！）

用系统 rg（见坑 2），对**打包完成的** app.asar 断言：

1. patch 后数组存在，如 `hs=[\`mcp_servers.${Ue}\`,ri]`（按本机构建实际命名）；
2. patch 前数组消失，如 `hs=[\`features.js_repl\`` 无命中；
3. 关键逻辑原样保留，逐个数命中数并与 app.asar.orig 对比：
   - `sendAppServerRequest("config/batchWrite")`（来源机：4 处）
   - `async function _s({appServerConnection`（1 处）
   - `BrowserUseThreadConfig`（>=1 处）
   - `mergeStrategy:"replace"`（来源机：6 处，patch 前后必须一致）
4. asar 头部 unpacked 标记：解析头部 JSON（偏移 12 起读 UInt32 长度），核对 `.node`、`winpty-agent.exe`、better-sqlite3/lib、node-pty/lib、.bin 相关文件全部有 `unpacked:true`，且没有错标。

`scripts/verify-js_repl.ps1` 已自动化以上检查（计数阈值按本机 orig 对比得出，不硬编码）。

## 动态验证

1. 备份 `%USERPROFILE%\.codex\config.toml`（整文件，不只一行）；
2. 手工设 `[features] js_repl = true`；
3. 启动 patched Codex，再重启一次；
4. diff **整个** config.toml：js_repl 应仍为 true，且其它段落无丢失（issue #29234）；
5. 在 patched Codex 里新开 projectless 任务，确认 `mcp__node_repl__js` 可用；再验证 project-backed 任务。

## 来源机踩过的坑（每一条都真实发生过）

### 坑 1：asar extract 不清理目标目录，旧构建文件混入

`work\asar-src` 里曾同时存在两个版本的 main bundle（2.6MB 旧版 + 16.4MB 另一版本），导致第一次 patch 打在了 app 根本不加载的文件上（惰性 patch）。教训：

- 解包前 `Remove-Item` 目标目录；
- patch 前确认目标文件确实来自当前安装版本（对照 `package.json` 的 main 链路与文件清单）；
- 最终验证必须打在**打包后的 asar** 上（来源机最终 asar 经逐字节复核：原包 4 处 js_repl -> patched 包 3 处，少的正是 keypath 数组里那一处）。

### 坑 2：包内 rg.exe 无法执行

`WindowsApps` 下的 `rg.exe` 受 ACL 限制，直接跑报"拒绝访问"。用系统安装的 rg，或用 .NET `System.IO.File` 读字节自行搜索。

### 坑 3：--unpack 的 glob 不跨路径

`--unpack '*.node'` 实测不生效，6 个 .node 文件全部 MISSING unpacked 标记。改用 `--unpack-dir` 按目录声明（清单见 02 文档第 4 步）。

### 坑 4：混淆名随版本漂移

不同构建里同一逻辑的变量名不同（hs/Ue 与 Ro/dh/ua 都见过），bundle 文件名带内容哈希。任何"照抄上一台机器 patch 字符串"的做法都会失败或打出惰性 patch。脚本按结构模式定位，不做字符串硬编码。

### 坑 5：运行中的 Desktop/其它会话可能动你的工作目录

来源机曾观测到 `work\asar-src` 内容在两条命令之间被还原成旧状态（时间戳对不上）。patch 前先删后建、patch 后立即重打包并当场验证，缩短窗口。

### 坑 6：config.toml 全量 diff

issue #29234：重启静默丢配置段落。只 diff js_repl 一行会漏掉其它损失。

## 第二阶段（仅当 patch 后工具仍缺失时）

工具是否暴露由 capability 协商决定；`removed` 短路判定大概率在 Rust 核心 `codex.exe`（约 297MB 二进制）里。逆向二进制难度和风险都远高于 asar，先确认第一阶段确实没解决问题再动手。注意来源机反例：js_repl=false 时工具依然可用，所以"工具缺失"要先排除其它原因（模型/账号的 desktopFeatureAvailability 结果）。
